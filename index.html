雲端搭檔
三件套入門

Worker、D1、FCM 聽落好深？其實可以先當成一隊幫手：有人做事、有人記低、有人送通知。

我哋會用「煲湯夠鐘，手機收到提醒」做例子，一步一步睇清楚佢哋點合作，以及點樣先將一個小程式放上網。

先明白用途再學步驟唔需要一開始用齊所有工具
開始學習 ↓

先記住一句：網頁俾人用；Worker 負責做事；D1 幫手記低；FCM 負責送通知。

第一課｜先睇生活例子

假設你想：煲湯 45 分鐘後提醒我

你用手機開一個網頁，輸入「45 分鐘後提醒我熄火」。之後你關掉網頁、鎖上手機。問題係：咁耐之後，邊個記得提醒你？

可以想像成一間小店接到一張「提醒單」

手機上的網頁負責收你填的資料；雲端幫手負責保存和處理；時間到了，再交給通知速遞員送去你的手機。

1｜你填資料「45 分鐘後叫我熄火。」
2｜雲端記低記住提醒內容、時間和送去哪部裝置。
3｜時間到了雲端按排程檢查有沒有到時的提醒。
4｜手機收到推播服務把通知送到手機，手機顯示提醒。
重要：如果只是一個普通網頁計時器，關掉網頁後，它通常就不能靠自己繼續計時。要關掉網頁後仍收到推播，還要另外做好雲端排程、通知服務、手機權限和網頁背景接收設定；不是把網頁放上網就自動完成。

第二課｜認識每個角色

其實唔係三個都做同一件事

另外先認識「網頁寄存」：它是放網頁給人看的地方，不等於 Worker。下面用小店做比喻。

先讓網頁上網

Cloudflare Pages｜網頁的公開地址

把 HTML、圖片、樣式等前台檔案放上網，別人就可以用網址打開。

好比：小店門面和招牌，讓客人找得到。

Cloudflare

Worker｜接單和處理事情的店員

收到網頁送來的要求後，按規則做事，例如檢查資料、計算結果、查詢資料庫或呼叫其他服務。

好比：看懂訂單、決定下一步的店員。

Cloudflare

D1｜雲端的資料表

把需要長期保存的資料放好，例如提醒文字、時間和目前是否已送出。它像一張有欄位的試算表，但由程式管理。

好比：店裡的訂單簿，方便日後翻查。

Google Firebase

FCM｜推播通知的派件員

由你的伺服器交出訊息和收件裝置資料，再由 FCM 協助把推播傳到支援的手機或瀏覽器。

好比：把提醒送往正確地址的速遞員。

「Cloudflare Worker」和「Cloudflare D1」屬於 Cloudflare；「Firebase FCM」屬於 Google Firebase。Pages 可以用來放靜態網頁。想看官方介紹：Cloudflare Pages、Workers。

第三課｜跟住一張提醒單行一次

「煲湯夠鐘」的通知，點樣由網頁去到手機？

把複雜的技術流程先簡化成五步。實際程式仍要設定每一個連接位。

1

你在網頁按「建立提醒」

網頁把提醒內容、預定時間和目標裝置的識別資料送去 Worker。這個「送出要求」可以想成把訂單交給店員。

手機 → Worker
2

Worker 把提醒寫進 D1

例如新增一行：「熄火提醒｜今晚 7:45｜未送出」。這樣就算你關掉網頁，資料仍然留在雲端。

Worker → D1
3

設定好的排程叫 Worker 檢查

要由你設定排程觸發（例如每隔一段時間檢查一次）。Worker 被叫醒後，查看 D1 有沒有到時而且未送出的提醒。

排程 → Worker → D1
4

時間到了，Worker 請 FCM 派件

Worker 取出提醒內容和收件裝置資料，再使用安全保管在伺服器的憑證，請 FCM 傳送推播。

Worker → FCM
5

手機或瀏覽器顯示通知

如果使用者已允許通知、裝置和瀏覽器支援、網絡及系統設定正常，手機便可以顯示推播。送出後，程式亦應把這行資料標記為「已送出」，免得重複提醒。

FCM → 手機
唔使背技術名：你只要記得「資料先存好 → 排程到時檢查 → 通知服務負責派送」。FCM 不會自己知道你的湯幾時煲好；Worker 和排程才負責決定幾時送。

第四課｜先選最少的工具

不是每個程式都要「三件套」

選一個最接近你想做的功能，看看大概需要甚麼。你可以先由最簡單版本開始。

選項只作入門方向，實際組合會按你的功能改變。

先由簡單計算機開始

HTML 網頁

如果只要在目前裝置做簡單計算，先做網頁就可以；資料不必送去雲端，亦不必先申請 D1 或 FCM。

第五課｜從想法到上網的次序

一步一步做，唔好一開始做晒

用「煲湯提醒」做例子。每做完一步先試清楚，再決定要不要加下一樣。

1

用一句說清楚你要做甚麼

例如：「我想輸入一個時間，之後收到『記得熄火』提醒。」先不要想太多工具，先把使用者要做的事說清楚。

目標：知道要解決甚麼問題

2

先做好一張簡單網頁

做出輸入框、按鈕和提示文字。第一版可以只在網頁開著時試功能，不用先做雲端通知。

  • 輸入：「45 分鐘」
  • 按鈕：「設定提醒」
  • 畫面顯示：「已設定，預計 7:45 提醒」

這一步學的是前台：使用者看見和按到的部分。

3

把網頁放上網，取得網址

靜態網頁可以放到像 Cloudflare Pages 這種寄存服務。常見做法是上載網站檔案，或連接程式碼專案；部署完成後會有一個 HTTPS 網址可以打開。

記住：這一步只是讓人看得到網頁，不代表提醒已經能在背景運作。

4

有雲端工作要做，才加 Worker

例如網頁送來「幫我保存這個提醒」，Worker 就接收資料、檢查格式，再決定怎樣處理。它像一個接單的雲端小幫手。

如果你的程式不需要後台處理，就先不要加。

5

要長期保存或同步，才加 D1

建立資料庫和表格，再設定 Worker 可以連到它（官方文件稱為 binding／綁定）。先把一筆測試提醒寫入，再讀回來確認。

想像表格有幾欄：「提醒內容｜幾時提醒｜送去哪部裝置｜狀態」。

6

真的要推播，最後才加 FCM 和排程

這一步最需要留心，因為不是只貼一段設定碼就完成。

  • 網頁需要 HTTPS；設定通知權限和背景接收用的 service worker。
  • 每部裝置要先完成通知註冊，程式才知道推播送去哪裡。
  • Worker 要安全地保管發送所需的秘密憑證；不要寫進公開網頁程式碼。
  • 另外設定排程檢查 D1，夠鐘後再請 FCM 發送。

先用自己的手機做一次測試，確認按允許通知、鎖屏或把網頁放到背景後的實際表現。

Cloudflare 官方 D1 入門說明會示範建立資料庫，並把資料庫綁定給 Worker 使用；Firebase 官方網頁 FCM 文件則說明 HTTPS、通知權限及 service worker 等設定。介面名稱可能更新，做實際操作時請跟官方文件的最新版步驟。

把工具組合想成「按需要加零件」

的士車費計算機

單純輸入公里數計價：先做網頁就可以。不用推播，不一定需要資料庫。

第七課｜先避開幾個常見誤會

呢幾點記住，就唔容易搞亂

  • Worker 不等於一部永遠開著的家用電腦。它收到要求時會執行；要定時做事，就必須另外設定 Cron Trigger 等排程。排程代表按設定週期執行，不要當成精準到秒的鬧鐘。
  • FCM 不負責倒數時間。它主要協助送推播；「幾時要送」要由你的程式和排程處理。
  • 把網頁放上網，不等於它自動有資料庫或推播。Pages 放網站；Worker、D1、FCM 各自需要設定和程式配合。
  • 推播不是保證一定響。用戶要允許通知；瀏覽器和裝置要支援；網絡、電量設定和系統設定亦可能影響顯示。
  • 「免費」不是永遠不變的承諾。服務方案、免費額度和收費規則可能改變。正式部署前先看當時官方方案及用量，不要假設永遠免費或無上限。
  • 私人憑證不要放進 HTML。HTML 會送到使用者的裝置上；可以讓 Worker 保管伺服器用的秘密，避免公開洩漏。

小字典｜遇到英文唔使驚

六個常見字，白話解釋

前台／網頁使用者看見、輸入資料和按按鈕的畫面。
後台／伺服器在雲端替網頁處理工作，不是使用者眼前的畫面。
資料庫有欄位、可以新增和查找資料的雲端記錄簿。
部署／上線把程式放到網上服務，讓網址可以打開或讓後台可以執行。
API兩個程式互相傳資料或請對方做事的一個入口。
Token／裝置識別資料幫推播服務找到目標裝置的識別資料；不是收件人的普通姓名，也不應隨意公開。

最後複習｜今日記住四句就夠

你已經有一張簡單地圖

  1. 先做一個最小、能用的網頁，不要一開始就加所有雲端功能。
  2. Pages 幫你把網頁放上網；Worker 幫你在雲端處理要求。
  3. D1 保存要記住的資料；FCM 協助派送推播。
  4. 要關掉網頁後收到提醒，還要有排程、資料、推播設定和裝置權限。

下一步建議：先畫出你自己的「手機 → Worker → D1／FCM」簡單流程，再只做第一個小功能。每一步做通，才加下一個零件。
